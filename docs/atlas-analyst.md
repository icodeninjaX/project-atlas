# ATLAS Analyst: implemented contract

This document describes the original seven-question Analyst flow at `/analyst` and `POST /api/analyst`. That endpoint authenticates every POST, accepts only a listed question template, and uses the signed-in Supabase client with an explicit `user_id` filter. RLS remains the final owner boundary. The model receives no database credentials, SQL facility, record mutation tool, or full record text. The separate [Phase 11 freeform flow](analyst-freeform.md) uses the accepted planner and read-only tools on the same page.

## Questions and data

| Question                                               | Retrieval and deterministic result                                                                                                                                                                                                                                                                                                                                                                          | Limit and data status                                                                                                                                                                                                                    |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What changed in my spending this month?                | `transactions(id, category_id, amount_centavos, transaction_date)` for expenses only, plus `transaction_categories(id, name)` for display labels. Current Manila month to today versus days 1–the equivalent elapsed day of the previous month. ATLAS sums integer centavos, computes change and percent change, and shows up to five largest absolute category changes. Income and transfers are excluded. | Up to 1,000 transactions across two months and 500 categories. A missing prior comparison period is insufficient. A row cap or unequal month lengths is partial. A zero-current-spending period can be compared if prior expenses exist. |
| Am I making progress toward becoming debt-free?        | `debts(id, original_balance_centavos, current_balance_centavos, status, created_at)`. Current balance, original principal, principal reduction, paid debt count.                                                                                                                                                                                                                                            | 500 debts; partial beyond cap. This is not a balance history or forecast.                                                                                                                                                                |
| What should I focus on this week?                      | `tasks(id, priority, due_at, scheduled_for)` for open tasks. Counts open, high/critical, and due or scheduled in the next seven Manila days.                                                                                                                                                                                                                                                                | 1,000 tasks; partial beyond cap. Titles and notes are excluded.                                                                                                                                                                          |
| Which area of my career pipeline is weakest?           | `job_applications(id, stage, next_action_at)`. Current stage counts and overdue next actions.                                                                                                                                                                                                                                                                                                               | 1,000 applications; partial beyond cap. No conversion-rate claim from snapshot counts.                                                                                                                                                   |
| How are my goals progressing?                          | Active `goals(id, progress_percent, target_date)` and `goal_milestones(id, goal_id, completed_at)`. Current active/overdue goals, completed milestones, and average displayed progress.                                                                                                                                                                                                                     | 500 goals and 1,000 milestones; partial beyond cap. No historical progress trend.                                                                                                                                                        |
| What patterns do you see in my last 12 weekly reviews? | `weekly_reviews(id, week_start, energy_score, stress_score, overall_score)`. Count and rounded average available scores in up to 12 completed reviews.                                                                                                                                                                                                                                                      | At least two completed reviews; fewer than 12 is partial. Written reflections are not interpreted.                                                                                                                                       |
| What are my current Signals?                           | Existing deterministic Signals engine; type, domain, and severity only.                                                                                                                                                                                                                                                                                                                                     | Up to 12 signals; partial beyond cap.                                                                                                                                                                                                    |

The route rejects other wording and domains before private retrieval. In particular, it does not answer broad financial diagnoses, infer causes of spending changes, summarize written reflections, recommend what to stop doing, predict debt payoff, or perform actions.

Task focus evidence also links up to three tasks ranked by this-week dates and priority. Weekly review evidence compares the most recent half of completed reviews with the earlier half when both have overall scores.

When spending retrieval reaches its cap, Analyst reports only the number of inspected records and explains that a reliable comparison cannot be calculated from the partial history. It does not present truncated sums as monthly totals.
If an incomplete current month has more elapsed days than the entire previous month, the comparison stops at the previous month's last day and labels the current-month remainder as excluded. A completed month with unequal month lengths is labeled partial and displays both period lengths.

## Evidence and provider boundary

Each evidence item has `id`, `metric`, `value`, `unit`, `period` (`from`, `through`), `comparisonBasis`, `source` (`description`, bounded `recordIds`, `href`), and `completeness` (`complete`, `partial`, `insufficient`). The package adds question type, overall status, and a plain-language note. The UI displays server evidence and record links even if OpenAI fails. Its figures come only from this package. Stored titles, notes, and review prose are excluded from retrieval; category labels are displayed locally and replaced with a generic label in the model payload. The prompt treats all supplied data as untrusted. Structured model output must contain a short qualitative explanation, cited evidence IDs, and uncertainty. Invalid IDs, malformed output, or numeric claims trigger an evidence-only fallback.

The UI requires an explicit data-sharing acknowledgement before each request. The disclosure explains that relevant personal facts go to OpenAI under the organization’s current data-sharing settings. The server uses a separate Analyst model allowlist: `gpt-4o-mini-2024-07-18` (default), `gpt-4.1-mini`, `gpt-5.4-nano`, `gpt-5.4-mini`, `gpt-4o`, `gpt-5.4`, `gpt-6-astra`, `gpt-6-sol`, and `gpt-6-luna`. Astra uses low reasoning; Sol and Luna use no reasoning for short evidence-bound explanations. It also enforces a 200-character question cap, 10,000-character evidence payload cap, 350 output-token cap, and a 12-second timeout. A separate per-user Analyst ledger allows eight requests per hour, 25 per day, and 300 site-wide per day. It records only type, model, timestamp, outcome, and token counts. It never stores prompts, facts, answers, or secrets.

When the model quota is reached or the provider fails, the UI still shows the calculated evidence without an AI explanation. The fallback message distinguishes quota exhaustion, model configuration, database setup, and provider failure; it never labels a configuration or provider error as a user quota error.

Reservation uses the typed `reserve_ai_analyst_request_result` RPC. Its statuses are `reserved` (with a request ID), `unauthenticated`, `invalid_type`, `invalid_model`, `hourly_quota`, `daily_quota`, and `site_quota`. The legacy bigint reservation RPC remains available during rollout for older deployments, but the Analyst route no longer uses its ambiguous `NULL` result. Missing RPCs are reported internally as `setup_required`; unexpected RPC results are `quota_unavailable`.

The hosted ProjectAtlas database initially lacked the GPT-6 allowlist migration. Its live `reserve_ai_analyst_request` definition accepted the six earlier models but rejected `gpt-6-astra`, `gpt-6-sol`, and `gpt-6-luna` by returning `NULL`; the route then incorrectly rendered `Analyst limit reached` without calling OpenAI. The GPT-6 allowlist and typed reservation migrations were applied through the hosted migration workflow as versions `20260924093543` and `20260924094513`. Their repository files, `20260924093543_add_gpt6_analyst_models.sql` and `20260924094513_analyst_typed_reservation.sql`, match those hosted versions. The live function definitions and grants match the repository SQL: GPT-6 reservations return `reserved`, invalid models return `invalid_model`, authenticated users can execute the RPCs, and `anon` cannot.

The audit ledger records typed provider outcomes including `success`, `context_limit`, `invalid_response`, `timeout`, `openai_auth_error`, `openai_model_access`, `openai_rate_limit`, `openai_invalid_request`, and `openai_provider_error`. Safe operational logs include only the feature, analysis type, requested/resolved model, reservation status, whether the provider was called, HTTP/request metadata, token counts, and latency. Prompts, questions, evidence, financial values, credentials, and authorization tokens are not logged or persisted.

## Validation

Focused route tests cover typed reservation success, invalid-model and quota rejection without provider calls, missing RPC setup, provider HTTP categories, timeout, evidence ID validation, payload minimization, and GPT-6 reasoning settings. Local pgTAP covers RLS isolation, independent quota, all nine allowed models, invalid type/model results, hourly/daily/site boundaries, authenticated-only execution, and the private audit ledger.

Validation on 2026-09-24: the focused Analyst route suite passed 20 tests; local `supabase db reset --local` applied all migrations; `supabase test db` passed 109 tests; full `npm test` passed 343 tests; `npm run lint`, `npm run typecheck`, and `npm run build` passed; and Playwright passed 38 browser tests with 38 credential-gated authenticated tests skipped. A rollback-scoped hosted SQL smoke test returned `reserved` for GPT-6 Astra, Sol, and Luna and distinct `invalid_model`/`invalid_type` results without persisting data. A live route smoke test used only synthetic evidence and the server-side OpenAI key: all three models returned HTTP 200, `providerStatus: success`, valid structured explanations, cited evidence ID `spending.current`, resolved model IDs matching the requests, and provider request IDs. OpenAI was therefore actually called for each model. A full hosted authenticated browser flow remains unverified because no disposable hosted account was used.
